# Provena agent entry point

Provena is a .NET 10 Minimal API for EUDR evidence collection and review. It does not determine legal compliance or submit DDS declarations.

## Working agreement

- This is the canonical instruction source for Codex and Claude Code. Tool adapters may import it, never duplicate project rules. Follow routed `.agents/skills` procedures even when not discovered natively.
- Read only the relevant route below, then its actual implementation and tests. Do not load all documentation by default.
- Work from the current checkout. Inspect `git status --short` before editing, preserve pre-existing changes, and avoid unrelated rewrites, formatting or destructive Git operations. Do not stage or commit without the user's request.
- Complete the coherent repository-level change: code, tests and only the supporting artifacts made stale by it. See [CHANGE_WORKFLOW](docs/CHANGE_WORKFLOW.md) for coordinated changes and handoffs.
- Ask only about unresolved product, legal, security, domain or architectural decisions; continue unambiguous work. Explicit owner decisions may replace earlier rules and must be recorded coherently.
- Code and executable tests describe current behaviour; unrun tests are not proof. Distinguish observations, intended rules, recommendations and unknowns. Never turn a security defect into a rule.
- **Current phase: local development only.** Do not introduce CI/CD, deployment or hosting configuration unless the owner changes this decision. Existing local Docker/PostgreSQL and integration tests remain supported. See [LOCAL_DEVELOPMENT](docs/LOCAL_DEVELOPMENT.md).

## Invariants every change must preserve

- Keep API → scoped service → DbContext boundaries. No repositories, CQRS, mediator, new projects or packages without a concrete approved need.
- Use thin Minimal API feature modules under `Endpoints/`, registered through `MapProvenaEndpoints()`, with `TypedResults`; never map endpoints in Program.cs. Internal routes belong to authorized `/api`. Upload groups use `WithUploadLimits()` and the documented cookie-free antiforgery opt-out. Update `EndpointInventoryTests` when routes change.
- Growing tenant-wide lists use `PageResult<T>`/`Common/Paging.cs`: default page 1, size 25, max 100, deterministic order with a unique tiebreak. Do not paginate small nested collections without need.
- Validate on the server. Preserve cancellation, transactions, per-case locks and post-lock public-token rechecks. Enforce tenant ownership for reads, writes and foreign references; never trust client `OrganizationId`.
- Public capabilities access one request/case only. No new `IgnoreQueryFilters` use without security review. Never expose internal notes, audit payloads, token hashes or storage keys publicly; never log secrets, tokens, public URLs or raw evidence.
- Read [DATABASE](docs/DATABASE.md) before persistence work. Never edit the frozen `InitialCreate.TargetModel.cs`. Do not bypass guards through other save overloads, bulk writes or raw SQL without explicit review and equivalent enforcement.
- Retained evidence is withdrawn/superseded, never overwritten/deleted; read current versions through `Current()`. Producers and plots are deactivated, not deleted. Supplier, Producer and ProductionPlot are distinct. Attribution pins exact plot revisions; never infer plots from supplier GeoJSON.
- Supplier submission is not acceptance. Geometry validity and completeness are not compliance. `ReadyForExport` is only an operational hint derived from requirement decisions; it is not the closure gate. Do not silently change those semantics.
- Case lifecycle v2 ([ADR 0009](docs/adr/0009-case-lifecycle-v2.md); it supersedes ADR 0008 only where 0008 says Owner reviews do not gate closure). Workflow status is `Draft`, `WaitingForSupplier`, `ReviewNeeded`, `ReadyForExport` or `Closed`; archive is an independent reversible dimension (`CaseArchival`), never a status. Close, reopen, archive and unarchive are Owner-only through the shared `OwnerGate` (live membership check before any case lookup or body read). Closing requires the latest Owner review to be Current and equal to `expectedReviewId`; one review backs at most one closure; the outcome is derived from the review decision; `ReturnedForCorrection` cannot close; `ExternalDdsCompleted` stores the authoritative External DDS record's reference number on the immutable `CaseClosure` (ADR 0011) and the other outcomes reject a reference; `ExternalDdsCompleted` also requires the current Quantity Reconciliation outcome to be `Matched` (409 `QuantityNotReconciled`, also for a Current policy-v1 review). Reopen needs the current closure id and a reason and preserves all history. Archive and unarchive need reasons. Closed or archived cases reject business mutations through `CaseService.EnsureMutable`; close and archive revoke supplier links, reopen and unarchive never restore them. Closure and reopening rows are immutable. Do not reintroduce `Completed`/`Archived` statuses, `CompletedAtUtc`, a case-level DDS reference (`EudrCase.ExternalDdsReference`), `POST .../complete` or shipment archival.
- External DDS Record v1 ([ADR 0011](docs/adr/0011-external-dds-record-v1.md); it amends ADR 0009 only on the source of the DDS reference) records an external submission fact, never EU approval, compliance or Provena verification, and makes no network call. `ExternalDdsRecord` is append-only: a correction is a new row superseding the single current one (only `SupersededAtUtc` null -> value may change); it points at the exact immutable `ReviewId`, which must be the latest, Current, `AcceptedAsCompleteUnderPolicy` review of the same case, and `submittedAtUtc` must be neither in the future nor before that review's `ReviewedAtUtc`. POST is Owner-only with optimistic concurrency (`expectedLatestExternalDdsRecordId`; 409 `ExternalDdsHistoryChanged`); replacement needs a reason and is not an EU amendment. Recording does not require Matched quantities; closing does. `ExternalDdsCompleted` checks, in order, stale review, Quantity Reconciliation, then the record (409 `ExternalDdsRecordMissing`, `ExternalDdsReviewMismatch`, `ExternalDdsReferenceMismatch`); the legacy `externalDdsReference` close field is optional, never authoritative and must equal the record's `ReferenceNumber`. `CaseClosure.ExternalDdsReference` is the only legacy field; `EudrCase` has none. `VerificationNumber` is access-enabling: return it only from the three External DDS endpoints, never in other DTOs, ProblemDetails, audit text or logs.
- Quantity Reconciliation v1 ([ADR 0010](docs/adr/0010-quantity-reconciliation-v1.md)) is derived, never stored or overridden: exact decimal equality in one unit, no conversion, no tolerance, for Shipment == current CaseLot (pilot single-lot assumption: one shipment/case has one current lot, not a multi-lot rule), supplier-confirmed quantity == Shipment (unit implied; every existing value is compared; `NotRequired` waives it only with a nonblank reviewer note, like `REQUIREMENT_QuantityConfirmation`; `IsRequired` is not consulted) and producer contributions == lot. A non-matched result blocks `AcceptedAsCompleteUnderPolicy` and `ExternalDdsCompleted` closing but never `ConfirmedOutsideRegulatoryScope`/`ConfirmedUnsupportedFlow`. A differing supplier quantity is accepted on submission. Fingerprint and snapshot stay version 1.
- Case master data changes through explicit audited refresh. Reviews and their snapshots are immutable and Owner-only; reviewed exports use stored history, not the live catalogue. For any dossier/completeness/review change, read [EUDR_DOMAIN engineering invariants](docs/EUDR_DOMAIN.md#engineering-invariants-for-domain-changes) and ADR 0008 (plus ADR 0009 for closure and archive) before editing; they retain fingerprint, lock-order, pinning and freshness rules.
- Do not weaken tests, authorization, tenant boundaries, validation or warnings-as-errors to obtain a pass.
